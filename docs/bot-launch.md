# Запуск Telegram-бота

Серверу нужны DATABASE_URL, TELEGRAM_BOT_TOKEN (настоящий токен), OWNER_TELEGRAM_ID=998579758. APP_URL=https://magazin-orcin-kappa.vercel.app/; при отсутствии переменной используется этот же адрес. NEXT_PUBLIC_BOT_USERNAME=magazinptz_bot.

Владелец открывает магазин кнопкой Mini App в Telegram → Управление → Telegram-бот → Подключить бота. Сервер проверяет подписанный Telegram-вход и роль владельца, проверяет имя бота, настраивает меню, команды /start и /help и webhook. Токен не передаётся браузеру. Общедоступной кнопки настройки нет. Demo-профили и браузерный вход не дают права запускать настройку.

TELEGRAM_WEBHOOK_SECRET можно задать явно (32–256 символов: A–Z, a–z, цифры, _ и -). Если не задан, сервер получает стабильный секрет HMAC из токена. При смене токена нужно повторить подключение. Pending updates не удаляются. Ошибки Telegram возвращаются без токена.

Если в боте ещё нет кнопки магазина, в @BotFather выберите /mybots → @magazinptz_bot → Bot Settings → Menu Button и укажите URL магазина и подпись «Открыть магазин». Затем откройте приложение этой кнопкой под аккаунтом владельца и выполните подключение.

Очередь уведомлений включается автоматически при подключённой базе; требуется db/002_notifications.sql. Внешний планировщик повторных попыток описан в withdrawals-notifications.md. Команды /start и /help сохраняют сообщение для получателя в приложении до отправки в Telegram. Реальная проверка требует нажатия /start пользователем; тесты не отправляют сообщения и не используют настоящий токен.

Расширенные кабинеты CRM и продавцов всё ещё доступны в preview. Эта настройка подключает бота и серверный магазин, не переносит данные из браузерного деморежима в PostgreSQL.

Приветствие читает название и описание из таблицы settings при каждом /start или /help. У владельца и заместителя — описание управления; у покупателя — инструкция по покупке. Уже отправленные исторические сообщения не редактируются.
