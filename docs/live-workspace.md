# Серверный кабинет магазина

## Включение

Новые таблицы и новый серверный путь включаются владельцем: откройте Mini App через Telegram → Управление → «Включить CRM и сохранение в базе». Роль и подпись Telegram проверяются сервером. Перед изменением проверяется ID проекта в DATABASE_URL: по умолчанию svshagbdpepzzlztxgqd, для отдельной установки задайте SUPABASE_PROJECT_REF.

До нажатия кнопки работает прежний серверный путь. Сама загрузка сайта не создаёт таблицы. Активация добавляет shop_state и bot_support_requests, включает RLS и закрывает прямой доступ anon/authenticated. Существующие таблицы, записи и ограничения ролей не удаляются и не меняются. Повторное нажатие не перезаписывает данные. Профили, каталог, заказы и бонусы импортируются из текущей базы, а не из browser preview. При переключении устаревший запрос не может записать данные через старый путь.

## Хранение и права

Полный рабочий граф магазина — каталог, категории, объявления, поставки, склад, ревизии, перемещения, бонусы, ставки, расходы, выводы и роли сотрудников — хранится в shop_state.data как JSONB. Это единое авторитетное хранилище операционных данных. Старые нормализованные таблицы каталога и заказов после импорта остаются историческими; не редактируйте их вручную в обход приложения. Название и описание синхронизируются в settings для бота. Профили Telegram и реферальные старты остаются в исходных таблицах. Владелец определяется существующей записью ownership; назначение заместителя не даёт права сменить владельца.

Изменение проходит в транзакции с SELECT FOR UPDATE строки магазина, поэтому склад, резерв выплат и доход не могут независимо измениться двумя параллельными запросами. В браузер возвращается проекция по роли: покупатель не получает закупочные цены и финансы персонала, продавец — чужие финансы и ожидаемые остатки ревизии. Роли для операций берутся из серверного состояния. Незарегистрированному username роль не выдаётся: человек сначала открывает Mini App, чтобы получить подтверждённый Telegram ID.

CRM использует те же расчёты, что проверены в preview. Старые расходы localStorage не включаются в реальные финансы. Демоаккаунты и годовые демоданные автоматически не импортируются. Уникальные посещения считаются по подтверждённому Telegram ID за день, дни — по Москве.

## Бот и обращения

/start читает текущее название, описание и logo_url. Пустые фото и описание не заменяются заглушками. В приветствии нет имени, ID или роли владельца. Есть магазин, заказы, бонусы, рефералы, сотрудничество, аренда, жалоба и помощь. Сотрудничество ведёт к текущему заместителю; если публичного username нет — принимается обращение через бот. Аренда описывает предложение и ведёт к владельцу. Это запрос условий, не автоматическая платная подписка.

Жалоба принимается ответом на сообщение самого бота. Проверяется ID отправителя, приватный чат и принадлежность сообщения-формы этому боту. Заявка содержит имя, username и Telegram ID отправителя. Жалобы и сотрудничество доступны владельцу и заместителю; аренда — только владельцу. Ответить можно в Управление → Обращения, ответ отправляется в бот клиента.

Любое серверное уведомление сначала сохраняется в app_notifications. Владелец получает отдельные тематические копии всех событий: заказы, выплаты, сотрудники, обращения, аренда. Номер карты и банковские реквизиты в текст уведомлений не включаются. Уведомления доступны и в кабинете. Фото отправляются через sendPhoto, при недоступном необязательном изображении текст и кнопки сохраняются.

Проверенные изменения allowed_updates для callback-кнопок применяются при следующем настоящем /start на уже подключённом webhook; заново подключать бота после обычного обновления не нужно. Нажатие /start получателем необходимо для возможности сообщений от Telegram-бота. Очередь имеет повторные попытки; для гарантированного фонового повторного запуска без новых действий настройте планировщик обработчика /api/notifications/dispatch согласно withdrawals-notifications.md. Реальное банковское перечисление при выводе выполняется вручную.
