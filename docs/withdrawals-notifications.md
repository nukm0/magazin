# Вывод заработка и Telegram

Продавец: «Мой заработок» → «Запросить вывод». Минимум задаётся владельцем или заместителем в CRM → «Выводы». Заявка резервирует сумму; повторный запрос с тем же идентификатором не списывает её снова. Отклонение с причиной возвращает резерв. Одобрение фиксирует решение, а банковский перевод руководство выполняет вручную. Реквизиты доступны в подробностях заявителю и руководству, в текст уведомлений не включаются.

В демонстрации используются только вымышленные реквизиты. Расширенные функции продавцов и выводов пока сохраняются в браузере preview, не в общей серверной базе. Демособытия не отправляются реальному боту. Для реальной эксплуатации требуется перенести эти операции в серверную базу и вызывать очередь в их транзакциях.

Обычный сайт позволяет просматривать каталог. Для заказа требуется Telegram Mini App: сервер проверяет подпись initData и срок действия, затем привязывает заказ к Telegram ID. Демонстрационный режим явно отделён и не подтверждает личность. В карточке покупателя кнопка открывает личный чат по публичному username с черновиком сообщения; если username отсутствует, доступно копирование текста. Документация: https://core.telegram.org/bots/webapps#validating-data-received-via-the-mini-app и https://core.telegram.org/api/links.

## Серверные уведомления

Для существующих серверных заказов и /start подготовлена таблица app_notifications и очередь. Примените актуальный db/001_initial.sql (включая buyer_telegram), затем db/002_notifications.sql. Нужны DATABASE_URL, TELEGRAM_BOT_TOKEN, APP_URL (боевой HTTPS URL), TELEGRAM_WEBHOOK_SECRET, NOTIFICATIONS_ENABLED=1. До применения миграции флаг должен оставаться 0. Секреты хранить только на сервере.

После серверного события уведомление сначала сохраняется для получателя в приложении, затем отправляется в Telegram. Клиент не может передать произвольный текст для отправки. Повторное создание источника не дублирует запись. Ошибки отправки остаются в очереди, без токена в журнале. При потере ответа Telegram редкое повторное сообщение возможно.

Для повторных попыток настройте внешний планировщик GET или POST /api/notifications/dispatch с Authorization: Bearer NOTIFICATION_CRON_SECRET (случайная строка от 32 символов). Обработчик также доступен подтверждённому владельцу/заместителю. Планировщик и переменные этим изменением не настроены; миграции на удалённой базе не выполнялись. Не включайте отправку для тестовых ID.

Уведомления и кликабельные логи действий доступны руководству в «Управление» → «Уведомления и логи». Получатель видит собственные уведомления в кабинете. Выключение Telegram-уведомлений не удаляет сообщения внутри приложения.
