# magazin — магазин внутри Telegram

Первая версия Telegram Mini App для одного магазина. TypeScript, Next.js App Router, React и PostgreSQL. Бот: [@magazinptz_bot](https://t.me/magazinptz_bot).

## Что работает в коде

- Вход по подписанным данным Telegram: ID, имя, фамилия, username. Телефон и email Telegram автоматически не передаёт.
- Покупатель: каталог, карточка товара, поиск по названию/описанию, категории/подкатегории, фильтры цены/наличия, сортировка, корзина, создание неоплаченного заказа, история заказов, личная тема.
- Управление внутри Mini App: создание/редактирование/скрытие объявлений, фото с устройства или HTTPS-ссылка; собственные категории и один уровень подкатегорий.
- Название/описание магазина; голубая, фиолетовая или розовая тема; отдельный цвет подсветки карточек.
- До 8 баннеров, автопереключение каждые 5 секунд, стрелки, точки, пауза.
- Уникальные авторизованные посетители, количество заказов, оплаченные заказы и выручка за всё время.
- Первый владелец — Telegram ID из OWNER_TELEGRAM_ID (для этого проекта 998579758). Затем владелец хранится в БД.
- Владелец назначает и отзывает заместителей по ID, а также может передать магазин другому зарегистрированному пользователю внутри Mini App. После передачи прежний владелец становится покупателем. Заместитель управляет теми же разделами, но не назначает людей и не передаёт магазин.
- Реферальные ссылки, учёт приглашённых пользователей, настройка бонуса за приглашение и процента за покупки; отдельный журнал бонусов и баланс.
- Webhook бота: /start с кнопкой открытия магазина, защита отдельным секретом.

## Что ещё НЕ подключено

**Онлайн-оплата отключена.** Договора/подключения к платёжному сервису нет. Приложение не списывает деньги и не подменяет платёж переводом на карту. Заказ сохраняется со статусом «Ожидает подключения оплаты»; товар не резервируется и остаток не списывается.

Автоматическое начисление бонусов за покупки/рефералов, списание бонусов и возврат бонусов будут реализованы вместе с подтверждёнными платежами. Сейчас настройки сохраняются, реферальная связь записывается только при первом входе; неоплаченные заказы бонусов не дают. Владелец также не может вручную присвоить статус «Оплачен».

Для реального запуска требуются PostgreSQL, размещение на Vercel, новые секреты бота и настройка BotFather. Они не создаются автоматически. Статистика отражает только реальные записи БД, без выдуманных показателей.

## Локальный запуск

Нужны Node.js 22+ и pnpm 11.

1. Установите зависимости: `pnpm install --frozen-lockfile`.
2. Запустите `pnpm dev` и откройте [локальный магазин](http://127.0.0.1:3000).
3. Без подключений доступен [предпросмотр владельца](http://127.0.0.1:3000/?preview=1). Он начинает с пустого каталога, хранит данные только в localStorage браузера и не отправляет заказы. Это отдельный режим, он не даёт доступа к серверной админке.
4. Для настоящих данных скопируйте `.env.example` в `.env.local`, заполните настройки и выполните `pnpm db:migrate`.
5. Реальный вход работает только при открытии через Telegram и HTTPS. Для локального просмотра используйте предпросмотр.

Проверки: `pnpm typecheck`, `pnpm test`, `pnpm build`.

## Настройки Vercel

После создания аккаунта импортируйте репозиторий `nukm0/magazin`. Framework Preset: **Next.js**, корень проекта — корень репозитория, команда сборки — `pnpm build`. Подключите постоянную PostgreSQL и примените `db/001_initial.sql` к выбранной базе, например командой `pnpm db:migrate` с её DATABASE_URL в локальном .env.local.

Добавьте в настройки проекта переменные:

| Переменная | Что указать |
| --- | --- |
| TELEGRAM_BOT_TOKEN | Новый токен от BotFather. Серверный секрет; никогда не NEXT_PUBLIC_ |
| OWNER_TELEGRAM_ID | 998579758 — первый владелец; дальнейшая передача прав происходит внутри Mini App |
| NEXT_PUBLIC_BOT_USERNAME | magazinptz_bot, без @ |
| DATABASE_URL | Строка подключения PostgreSQL с TLS по настройкам поставщика |
| APP_URL | Постоянный HTTPS-адрес приложения после деплоя |
| TELEGRAM_WEBHOOK_SECRET | Случайная строка 32–256 символов: A–Z, a–z, 0–9, _ и - |

TELEGRAM_BOT_TOKEN, DATABASE_URL и TELEGRAM_WEBHOOK_SECRET храните как секреты. Для Preview используйте отдельного тестового бота и отдельную БД; основной webhook должен вести на Production. После изменения переменных выполните новый деплой.

Затем заполните те же значения локально и выполните `pnpm bot:setup`: команда установит кнопку меню и webhook. Она меняет настройки реального бота — запускайте после готовности Production. Сам токен не попадает в вывод.

В BotFather выберите вашего бота → настройку Main Mini App и задайте постоянный APP_URL. Это нужно в том числе для ссылок вида `https://t.me/magazinptz_bot?startapp=ref_<ID>`. После открытия магазина через бота у владельца появится раздел «Управление».

Пример токена из переписки в репозитории отсутствует. Если он был настоящим, перевыпустите его перед подключением.

## Хранение и ограничения первой версии

Данные, заказы, роли, картинки и журнал бонусов хранятся в PostgreSQL. Загруженные PNG/JPEG/WebP до 2 МБ выдаются отдельным маршрутом /api/media/[id], а не в общем JSON каталога. Фото предназначены для публичного каталога. Для большого каталога стоит перенести изображения в объектное хранилище.

Цены хранятся целыми копейками; суммы заказа сервер рассчитывает заново по каталогу. Повторная отправка одного заказа защищена ключом идемпотентности. Запись заказа не резервирует товар. Корзина хранится на конкретном устройстве отдельно для каждого Telegram ID и не синхронизируется между устройствами.

История показывает последние 100 заказов и начислений. Редактор ограничивает баннеры восемью. Сессия Telegram действует 1 час: при истечении закройте и снова откройте Mini App. Изменения ролей проверяются сервером при каждом действии, поэтому отозванный заместитель не может сохранять изменения со старой открытой страницы.

Журнал действий сохраняет тип административного изменения и ID исполнителя. Первый запуск пустой: товары и примерные категории не добавлены.

## Проверено

- Production-сборка и TypeScript.
- Модульные проверки HMAC Telegram, подделанных/просроченных данных, ролей, отзыва доступа, серверного расчёта цены и повторной отправки заказа.
- Мобильный интерфейс и предпросмотр; локальная проверка форм.

Полный сценарий с настоящими Telegram, постоянной PostgreSQL и платежами требует подключения сервисов. Тесты серверных действий используют подставной клиент БД и не заменяют интеграционную проверку транзакций.

Документация: [Telegram Mini Apps](https://core.telegram.org/bots/webapps), [платежи за физические товары](https://core.telegram.org/bots/payments), [Next.js](https://nextjs.org/docs).

## Локальный режим nukm0

Теперь `pnpm dev` запускает постоянную локальную SQLite и вход в тестовый профиль nukm0 (998579758). Для настоящих Telegram/PostgreSQL используйте `pnpm dev:telegram`. Локальный вход отключён при NODE_ENV=production, на Vercel и для внешних адресов. Тестовые платежи, возвраты, остатки, бонусы и их списание работают только локально. Данные не синхронизируются с Production. На этом компьютере кеш и база настроены в D:/Codex/magazin-local из-за отсутствия места на C.

## Опубликованная витрина Mide Shop

Без DATABASE_URL сайт показывает сохранённый публичный каталог из data/catalog.json и фотографии из public/catalog-media. Профили, заказы, роли и бонусные балансы локального режима не публикуются. Вход владельца и запись заказов требуют настоящих Telegram и PostgreSQL. Команда pnpm db:migrate создаёт схему и переносит каталог только в пустую базу с исходным названием магазина; существующие данные не перезаписываются.


## Демонстрация продавцов и заказов

В `/?preview=1` доступны владелец, покупатель, заместитель и два продавца. Демонстрационные одежда, посещения и заказы создаются только в браузерном предпросмотре. Склад, лента, причины возвратов, баланс и журнал сохраняются в localStorage этого браузера. Это не многопользовательский сервер: между устройствами данные не синхронизируются, а роли в демо не являются защитой приватных данных. Для реального запуска нужны серверные транзакции закрепления и резервирования, отдельные таблицы складов, журнала и заработка, авторизация и фильтрация данных на сервере. Эти новые операции пока отключены в реальном API.

В демо доставка всегда включена в итог. В смешанном заказе используется максимальный тариф товаров, независимо от количества. Настройка карточки управляет отдельным отображением доставки покупателю. Продавец видит свой заработок после завершения доставки, без стоимости доставки в карточке активного заказа. Реальных денежных переводов и встроенного чата нет; связь по введённому покупателем Telegram или телефону.
